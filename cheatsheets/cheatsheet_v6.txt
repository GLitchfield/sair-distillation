STRATEGY: Determine if Equation 1 implies Equation 2 by following these steps. Be concise—one line per magma test.

OUTPUT FORMAT WARNING: Final answer must use plain text headers with NO markdown formatting. Write exactly "VERDICT: TRUE" or "VERDICT: FALSE" — the colon must be immediately followed by a space and then TRUE or FALSE. NOT **VERDICT:** or any bold/italic formatting.

STEP 1: QUICK STRUCTURAL CHECKS

Check 1a - Singleton Detection:
If Equation 1 has the EXACT form "x = f(y, z, ...)" where:
  - The LEFT side is a SINGLE BARE VARIABLE (just "x" with no operations), AND
  - x does NOT appear ANYWHERE on the right side
Then Equation 1 forces the magma to be a singleton. Answer: TRUE.

WHY: For any fixed y,z,..., the RHS is some element e. Since x is universally quantified, EVERY element must equal e → singleton → satisfies all equations.

CRITICAL: This rule requires a BARE variable on LHS — NOT x inside a product.
  - "x = y * (z * w)" → YES singleton → TRUE
  - "x = (y * y) * ((y * z) * w)" → YES singleton → TRUE
  - "x * y = z * (w * y)" → NO (LHS is x*y, not bare x)
  - "x = x * (y * z)" → NO (x appears in RHS)

Check 1b - Disjoint Variable Sets (Constant Law):
If EQ1's LHS and RHS use COMPLETELY DISJOINT variable sets (no variable appears on both sides), EQ1 forces all products to be equal (the "constant law").
  - If EQ2 has * on BOTH sides → TRUE.
  - If EQ2 has a bare variable on one side → continue to Step 2 to confirm.
Examples:
  - EQ1: "x * y = z * w" → {x,y} vs {z,w} → disjoint → constant law
  - EQ1: "x * y = y * z" → NOT disjoint (y shared)

Check 1c - Variable Count Balance:
Count occurrences of each variable on LHS vs RHS of each equation.
An equation is "balanced" if every variable has equal count on both sides.

THEOREM: If EQ1 is balanced AND EQ2 is unbalanced → FALSE immediately.
(The addition magma x*y=x+y satisfies any balanced equation but fails unbalanced ones.)

Balanced: x*y = y*x (x:1=1, y:1=1). Unbalanced: x*y = x*x (y:1 vs 0). x*x = x (x:2 vs 1).

NOTE: XOR catches parity mismatches. Balance check catches additional cases with same parity but different counts (e.g., x appears 3 times LHS, 1 time RHS — both odd, XOR passes, but balance check catches → FALSE).

Check 1d - LHS Complexity:
If Equation 2's LHS has FEWER * operations than Equation 1's LHS, lean FALSE. Proceed to Step 2.

STEP 2: TEST SPECIFIC COUNTEREXAMPLE MAGMAS

Find a magma that SATISFIES EQ1 for ALL variable assignments AND VIOLATES EQ2 for some assignment.

LAW CHECK: A magma satisfies an equation as a LAW only if it holds for EVERY assignment. If testing shows the equation holds only when "x=z" or forces constants, the magma does NOT universally satisfy it — skip to next magma.

SINGLETON SIGNAL: If testing a magma against EQ1 reveals EQ1 forces "x = y" for all x,y → EQ1 only admits singletons → TRUE immediately. Example: right-projection on EQ1 x=y*(z*w) gives x=w for all x,w → singleton → TRUE.

TRIVIAL MODELS SIGNAL: After testing all magmas — if MOST/ALL fail to satisfy EQ1 (EQ1 is highly restrictive), and those FEW that do satisfy it (projections, constants, singletons) ALSO satisfy EQ2 → lean strongly TRUE. EQ1 collapses the model space so tightly that any remaining model satisfies EQ2. Proceed to Step 4 to prove it. Do NOT default FALSE in this situation.

Magma A - "Zero": x*y = 0 for all x,y.
  Rule: holds iff both sides contain * (both→0), or both sides are the same bare variable.
  Fails if one side is a bare variable (can equal 1) and the other contains * (equals 0).

Magma B - "Right Projection": x*y = y.
  Rule: any compound expression → its RIGHTMOST leaf variable.
  Equation holds iff both sides have the same rightmost variable.

Magma C - "Left Projection": x*y = x.
  Rule: any compound expression → its LEFTMOST leaf variable.
  Equation holds iff both sides have the same leftmost variable.

Magma D - "XOR": x*y = x+y mod 2.
  Rule: check EACH variable independently — it must have the same parity count (odd/even) on both sides.
  CRITICAL: Do NOT sum all variable counts together. Check every variable one at a time.

  WORKED EXAMPLE — checking equation x = (y*z)*x:
    x: LHS count=1 (odd),  RHS count=1 (odd)  → same ✓
    y: LHS count=0 (even), RHS count=1 (odd)  → DIFFERENT → XOR FAILS EQ1
    z: LHS count=0 (even), RHS count=1 (odd)  → DIFFERENT → XOR FAILS EQ1
  Result: XOR does not satisfy this equation. It is NOT a valid counterexample for anything.

  COMMON MISTAKE: "LHS total = 1 variable, RHS total = 3 variables, both odd → match ✓" — WRONG.
  Each variable must be checked individually, not totaled.

Magma E - "Constant 1": x*y = 1 for all x,y.
  Rule: holds iff both sides contain * (both→1), or both sides are the same bare variable.
  Fails if one side is a bare variable (can equal 0) and the other contains * (equals 1).

Magma F - "Negate-right": x*y = 1-y.
  Shortcut: x*y=1-y. So x*(y*z)=z. And (x*y)*z=1-z.
  Left-nested depth-n: result alternates 1-z / z. Right-nested: result is innermost variable.

Magma G - "Addition": x*y = x+y (integer addition).
  Rule: expression evaluates to SUM of all variable occurrences (each counted with multiplicity).
  Equation holds iff every variable appears the SAME NUMBER OF TIMES on both sides.
  Catches cases XOR misses: x appears 3 times LHS, 1 time RHS (both odd → XOR passes, Addition fails).

If any magma universally satisfies EQ1 but violates EQ2 for some assignment: FALSE.

STEP 3: TEST WITH LINEAR MAGMA OVER Z/3Z

Try x*y = 2x + y mod 3 (values {0,1,2}). Evaluate by computing 2x+y mod 3.

STEP 4: ATTEMPT ALGEBRAIC PROOF

If no counterexample was found (especially when Trivial Models Signal applies), try to prove TRUE.

ARGUMENT POSITION WARNING: When applying EQ1 as a rewrite rule, track which slot is left vs right.
If EQ1 says "A*B = C", then left-slot=A and right-slot=B. Substituting incorrectly swaps the meaning.

WORKED PROOF EXAMPLE:
  EQ1: x = y*x  [means: for all expressions E, F: E*F = F — right argument always wins]
  Goal: prove EQ2: x = x*(x*((y*z)*x))

  Identify the pattern: EQ1 says [anything]*[term] = [term].
  Step 1: (y*z)*x — right slot is x → apply EQ1 → (y*z)*x = x
  Step 2: x*x   — right slot is x → apply EQ1 → x*x = x
  Step 3: x*(x*((y*z)*x))
        = x*(x*x)   [by Step 1: replace (y*z)*x with x]
        = x*x       [by Step 2: replace x*x with x]
        = x         [by Step 2]
  ✓ EQ2 proved.

  KEY: Substitute innermost subexpressions first. Write out each step explicitly.
  Before each application, confirm: which is the left slot and which is the right slot?

Method 4a: Substitute specific values (x=y, or replace x with x*x, etc.) into EQ1 to derive intermediate identities, then chain them to reach EQ2.
Method 4b: Use EQ1 as a rewrite rule to transform one side of EQ2 into the other (as above).

STEP 5: DEFAULT JUDGMENT

WARNING: Do NOT say TRUE just because no counterexample was found. Do NOT say FALSE just because no proof was found. Both are common errors on hard problems.

Weigh all signals that apply:

→ Lean TRUE when:
  - Trivial Models Signal (Step 2): EQ1 is highly restrictive and all satisfying models also satisfy EQ2
  - EQ2 uses 2+ fewer distinct variables than EQ1
  - EQ1 is very strong (forces right/left projection or constant behavior)

→ Lean FALSE when:
  - EQ2 introduces new variables not in EQ1, AND EQ1 is not highly restrictive (many magmas satisfy it)
    EXCEPTION: If EQ1 is highly restrictive (Trivial Models Signal), new variables in EQ2 are irrelevant — lean TRUE instead
  - Check 1d applies: EQ2's LHS has fewer * than EQ1's LHS
  - EQ1 has the form "x*x = f(y,z,...)" or "f(...)*x = x" and standard magmas all fail EQ1 — likely a 3-element counterexample exists → lean FALSE

Choose the strongest signal. When signals conflict or are weak, prefer FALSE — the competition dataset is ~50% FALSE and spurious TRUE claims are harder to catch than spurious FALSE claims.

IMPORTANT REMINDERS:
- A magma is just a set with a binary operation. No associativity, commutativity, or identity assumed unless forced.
- TRUE means EVERY magma satisfying EQ1 also satisfies EQ2. One valid counterexample makes it FALSE.
- Constant magmas (A and E) satisfy any equation where both sides contain *.
