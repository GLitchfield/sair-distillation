STEP 1: QUICK STRUCTURAL CHECKS

Check 1a - Singleton Detection:
If Equation 1 has the EXACT form "x = f(y, z, ...)" where:
  - The LEFT side is a SINGLE BARE VARIABLE (just "x" with no operations), AND
  - x does NOT appear ANYWHERE on the right side
Then Equation 1 forces the magma to be a singleton. Answer: TRUE.

WHY: For any fixed y,z,..., the RHS is some element e. Since x is universally quantified, EVERY element must equal e → singleton → satisfies all equations.

CRITICAL: This rule requires a BARE variable on LHS — NOT x inside a product.
  - "x = y * (z * w)" → YES singleton → TRUE
  - "x = (y * y) * ((y * z) * w)" → YES singleton → TRUE
  - "x * y = z * (w * y)" → NO (LHS is x*y, not bare x)
  - "x = x * (y * z)" → NO (x appears in RHS)

Check 1b - Disjoint Variable Sets (Constant Law):
If EQ1's LHS and RHS use COMPLETELY DISJOINT variable sets (no variable appears on both sides), EQ1 is a very strong law that forces all products to be equal (the "constant law").
  - If EQ2 has * on BOTH sides → TRUE (both sides become the same constant).
  - If EQ2 has a bare variable on one side → continue to Step 2 to confirm.
Examples:
  - EQ1: "x * y = z * w" → {x,y} vs {z,w} → disjoint → constant law
  - EQ1: "x * (y * z) = w * u" → {x,y,z} vs {w,u} → disjoint → constant law
  - EQ1: "x * y = y * z" → NOT disjoint (y shared)

Check 1c - Variable Count Balance:
For each equation, count total occurrences of each variable on LHS vs RHS.
An equation is "balanced" if every variable appears the same number of times on each side.

THEOREM: If EQ1 is balanced AND EQ2 is unbalanced → FALSE immediately.
(The integer-addition magma x*y=x+y satisfies any balanced equation but fails any unbalanced one, giving a counterexample.)

Balanced examples: x*y = y*x (x:1=1, y:1=1). x*(y*z) = (x*y)*z (x:1=1, y:1=1, z:1=1).
Unbalanced examples: x*y = x*x (y:1≠0). x*x = x (x:2≠1).

NOTE: XOR (Magma D below) catches parity mismatches. The balance check catches additional cases where counts differ but parities match (e.g., x appears 3 times on LHS, 1 time on RHS — both odd, same XOR parity, but still unbalanced → FALSE if EQ1 is balanced).

Check 1d - LHS Complexity:
If Equation 2's LHS has FEWER * operations than Equation 1's LHS, lean FALSE. Proceed to Step 2 to confirm.

STEP 2: TEST SPECIFIC COUNTEREXAMPLE MAGMAS

Find a magma that SATISFIES EQ1 for ALL variable assignments AND VIOLATES EQ2 for some assignment.

LAW CHECK: A magma satisfies an equation as a LAW only if it holds for EVERY assignment. If an equation reduces to "x=z" or "x+y=0", the magma does NOT universally satisfy it — skip to next magma. Do NOT cherry-pick one assignment where EQ1 holds and a different one where EQ2 fails.

SINGLETON SIGNAL: When evaluating a magma against EQ1, if EQ1 reduces to "x = y" for arbitrary x,y (forcing all elements to be equal), then EQ1 only admits singleton models → answer is TRUE immediately. Example: right-projection gives EQ1 x=(z*w)=w, so x=w for all x,w → singleton → TRUE.

Magma A - "Zero": x*y = 0 for all x,y.
  Rule: holds iff both sides contain * (both→0), or both sides are the same bare variable.
  Fails if one side is a bare variable (can equal 1) and the other contains * (equals 0).

Magma B - "Right Projection": x*y = y.
  Rule: any compound expression → its RIGHTMOST leaf variable.
  Equation holds iff both sides have the same rightmost variable.

Magma C - "Left Projection": x*y = x.
  Rule: any compound expression → its LEFTMOST leaf variable.
  Equation holds iff both sides have the same leftmost variable.

Magma D - "XOR": x*y = x+y mod 2.
  Rule: equation holds iff every variable has the same parity of occurrences on both sides (same odd/even count). Any variable with different parity on LHS vs RHS → equation fails.

Magma E - "Constant 1": x*y = 1 for all x,y.
  Rule: holds iff both sides contain * (both→1), or both sides are the same bare variable.
  Fails if one side is a bare variable (can equal 0) and the other contains * (equals 1).

Magma F - "Negate-right": x*y = 1-y.
  Shortcut: x*y=1-y. So x*(y*z)=z. And (x*y)*z=1-z.
  Left-nested depth-n: result alternates 1-z / z. Right-nested: result is innermost variable.

Magma G - "Addition": x*y = x+y (integer addition).
  Rule: any expression evaluates to the SUM of all its variable occurrences (each counted with multiplicity).
  Equation holds iff every variable appears the SAME NUMBER OF TIMES on both sides.
  Use after Check 1c: if EQ1 is balanced (passes this magma) but EQ2 is unbalanced → FALSE.
  Catches cases XOR misses: e.g., x appears 3 times LHS, 1 time RHS (both odd → XOR passes, but counts differ → Addition fails → FALSE).

If any magma universally satisfies EQ1 but violates EQ2 for some assignment: FALSE.

If no counterexample was found, try to prove TRUE.

Method 4a: Substitute specific values (x=y, x=x*x, etc.) into EQ1 to derive intermediate identities, then derive EQ2.

Method 4b: Use EQ1 as a rewrite rule to transform one side of EQ2 into the other.

STEP 5: DEFAULT JUDGMENT

If no counterexample and no proof, weigh these heuristics:
- EQ2 introduces new variables not in EQ1 → lean FALSE
- EQ2 uses 2+ fewer variables than EQ1 → lean TRUE
- EQ2 has deeper nesting or more * operations → lean FALSE
- Step 1d pointed toward FALSE → lean FALSE
- All standard magmas (A-G) fail to satisfy EQ1 → EQ1 may only admit trivial models → lean TRUE

Choose the verdict that matches the strongest signal. Do not default to TRUE just because no counterexample was found.

- A magma is just a set with a binary operation. No associativity, commutativity, or identity assumed unless forced.
- TRUE means EVERY magma satisfying EQ1 also satisfies EQ2. One valid counterexample makes it FALSE.
